# 구현 설계와 제약

## 책임 분리

`PoseFrame`과 `MotionClassifier`는 KMP 공통 인터페이스입니다. Android MediaPipe 타입과 LiteRT 네이티브 실행은 별도 모듈에 있습니다. JVM 타깃은 공통 로직 테스트용이며 JVM용 LiteRT 실행기는 제공하지 않습니다. iOS는 이후 플랫폼 런타임 구현을 추가해야 합니다.

엔진·분류기·특징 추출기는 상태가 있으므로 동시에 호출하면 안 됩니다. 프레임 처리·reset·close를 동일한 직렬 실행 문맥에서 호출합니다. 샘플의 CameraX 분석·파일 기록·추론은 단일 작업 스레드에서 수행합니다. 카메라 프레임은 KEEP_ONLY_LATEST로 받아 쌓이지 않게 하며, 타임스탬프는 카메라 프레임의 나노초 값을 밀리초로 변환합니다.

`RecognitionMode.Auto`는 분류기를 요구합니다. `RecognitionMode.Guided(exerciseId)`는 분류기 없이 선택한 운동을 추적하며 운동 종류를 자동 판별한다고 주장하지 않습니다. 카운팅 설정은 `TrackingConfig`로 독립시키고 운동별 `ProgressConfig`를 재정의할 수 있습니다. 초기 준비 자세 확인 후, 정상 완료를 성립시킨 상단 안정 상태를 다음 반복 준비에 재사용합니다.

## 분류와 진행률

AI는 최근 특징 창에서 운동 종류를 분류하고, 운동별 상태 머신은 관절과 자세의 단계 순서를 확인합니다. 처음 15개 유효 시간행 이후부터 매 프레임 추론합니다. 입력 프레임 속도와 모델 입력 30Hz는 독립적입니다.

분류 확정에는 모델 점수 임계값, 1·2순위 점수 차이, 200ms 연속 일치가 필요합니다. 모델 점수는 확률로 보정하지 않았습니다. 운동별 잠정 상태 추적을 함께 유지해 분류가 늦게 확정되어도 이전 단계 관측을 이용합니다. 특징 창은 6초이고 반복 단계 상태는 최대 15초 유지합니다.

단계 추적의 기준:

- 스쿼트/푸쉬업: 준비 → 하강 → 기준 각도 도달 → 상승 → 최종 자세 안정. 0–50–100%.
- 점프스쿼트: 하강 0–40%, 상승·도약 40–70%, 공중·착지·서기 70–100%.
- 버피: 몸 낮추기 0–20%, 다리 뻗기 20–40%, 다리 당기기 40–60%, 상승·도약 60–80%, 착지·서기 80–100%.

안정 시간은 최종 판정 조건이며, 자세를 유지하는 것만으로 기하학적 진행률이 증가하지는 않습니다. 동일 반복에서는 진행률의 역행을 막습니다. 최저 기준 전에 올라오는 부분 동작은 반복으로 세지 않습니다. 시작 자세를 관측하지 못한 동작은 완료로 세지 않습니다.

완료 후보는 운동 ID·반복 시작 시각을 키로 한 큐에 보관합니다. 반복 중 확정한 분류 근거를 유지하므로 현재 분류가 `other`로 돌아가도 기존 후보가 삭제되지 않습니다. 자동 모드는 분류 근거가 없는 후보를 집계하지 않으며, 지정 모드는 기하학적 단계로 판정합니다. 완료 관측 후 기본 500ms 확인 구간을 거치고 기본 3000ms까지 후보를 보관합니다.

짧은 관절 유실에는 이미 관측된 완료를 보존하되, 관측 복구부터 확인 시간을 다시 측정합니다. 기본 200ms를 넘는 입력 간격도 연속 관측으로 인정하지 않습니다. 해당 운동의 정상 관측이 기본 500ms 넘게 끊기면 추적과 후보를 초기화합니다. 분류용 v1 특징 시계열의 500ms 초기화 규칙은 카운팅 설정과 별개로 유지합니다. 점프가 관측되면 해당 동작의 스쿼트 후보를 취소하며, 다음 반복의 점프로 이전 반복을 취소하지 않도록 시작 시각을 비교합니다.

`RepEvent`에는 `repId`, 운동 ID, 시작·기하학적 완료·발행 시각이 있습니다. `current`는 현재 프레임의 상태입니다. 이전 반복의 확인과 다음 반복의 진행을 별도로 표시할 수 있습니다. 한 호출에서 여러 완료 이벤트가 발행될 수 있습니다. 기존 최상위 결과 필드는 이벤트가 있는 호출에서 첫 이벤트를 표시하여 기존 소스 사용 방식을 유지합니다. 새 소비자는 `current`와 `events`를 사용해야 합니다.

카운팅 기하는 분류 특징과 분리합니다. 기본 추적기는 운동에 필요한 한쪽 관절을 visibility로 선택하고, 반복과 후보 확인 도중에는 측면을 바꾸지 않습니다. 스쿼트·점프스쿼트는 팔 좌표를 요구하지 않습니다. 사용자 정의 운동은 기본적으로 기존 전체 특징 추출기를 사용합니다. 부분 기하는 모델 입력으로 사용하지 않으며 기존 모델의 feature-v1 규격을 바꾸지 않습니다.

초기 구현은 관절 임계값과 영상 발목/골반 이동을 사용하는 휴리스틱입니다. 운동 자세의 정확성, 측정 장비 수준의 비행 판정, 모든 버피 변형을 보장하지 않습니다. 카메라 이동·가림·프레임 누락·신체 비율에 따른 오차는 실제 수집 데이터로 평가해야 합니다.

## 수집 앱과 라벨링

촬영 대상은 1인, 전신 노출, 고정 사선입니다. 수집 라벨은 저장 파일의 헤더에만 들어갑니다. 앱은 원본 영상과 오디오를 저장하지 않으며, 파일 내보내기는 Android 문서 선택기를 사용합니다. 참가자 ID를 동일하게 유지해야 train/test에 같은 사람이 섞이지 않습니다.

라벨링 도구는 외부 서비스 없이 브라우저에서 실행하며 좌표 골격 재생·프레임 이동·단계 기록·구간 삭제·라벨 다시 불러오기를 제공합니다. 원본 영상 없이 정확히 구분하기 어려운 자세가 있을 수 있으므로 데이터 수집과 검토 절차를 함께 점검해야 합니다.

재생 속도는 프레임 간격을 따라가되 긴 유실 구간은 최대 100ms 대기로 압축합니다. 엔진에는 원본 타임스탬프를 전달하므로 실제 시간 간격 기준으로 평가됩니다. 예측 내보내기는 파일 재생 결과에만 제공됩니다.

## 학습·확장

데이터는 먼저 참가자 단위로 train/validation/test로 분할합니다. 중복 세션 ID를 거부하고, 모든 분할에 모든 클래스가 있어야 합니다. 시계열 창과 표준화 통계는 분할 이후 생성합니다. 학습 순서와 분할 seed는 보고서에 기록합니다.

기본 모델은 32채널 causal Conv1D 6층(dilation 1,2,4,8,16,32), 마지막 시점 선택, softmax로 구성합니다. 실제 특징 수용 범위는 127시점입니다. `--architecture residual`은 dilation별 Conv1D 2개와 잔차 연결·dropout을 사용해 180시점 창 전체를 참조할 수 있는 비교 모델입니다. 입출력 특징 v1과 float32 softmax 규격은 동일합니다. `--classes`로 기본 운동 중 일부와 `other`를 선택할 수 있고, `--balance-classes`는 학습 클래스 빈도의 역수 가중치를 적용합니다. 성능 우위는 실제 데이터의 동일 분할로 확인해야 합니다.

가장 낮은 validation loss의 가중치를 내보냅니다. validation에서 확신도·마진 임계값을 선택하고 test는 최종 평가·변환 비교에만 사용합니다. 중단·불완전 반복은 운동 종류 정답을 유지하고 반복 집계 정답에서는 제외합니다. 큰 데이터셋에서는 현재의 메모리 기반 창 생성·학습 로더를 스트리밍 로더로 교체해야 합니다.

운동 추가 시 새 데이터·라벨링 단계·학습 출력과 `ExerciseDefinition`을 함께 추가합니다. 특징이 기존 운동을 구분하기 부족할 때는 특징 규격 버전을 올리고 Kotlin/Python 양쪽을 수정하며 공통 fixture도 갱신합니다. 런타임은 모델에 있는 각 운동 ID의 단계 정의를 요구합니다.

공개 저장소 배포·Maven 원격 업로드·실제 데이터 수집·iOS 구현은 이번 작업에서 수행하지 않습니다.
