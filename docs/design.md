# 구현 설계와 제약

## 책임 분리

`PoseFrame`과 `MotionClassifier`는 KMP 공통 인터페이스입니다. Android MediaPipe 타입과 LiteRT 네이티브 실행은 별도 모듈에 있습니다. JVM 타깃은 공통 로직 테스트용이며 JVM용 LiteRT 실행기는 제공하지 않습니다. iOS는 이후 플랫폼 런타임 구현을 추가해야 합니다.

엔진·분류기·특징 추출기는 상태가 있으므로 동시에 호출하면 안 됩니다. 프레임 처리·reset·close를 동일한 직렬 실행 문맥에서 호출합니다. 샘플의 CameraX 분석·파일 기록·추론은 단일 작업 스레드에서 수행합니다. 카메라 프레임은 KEEP_ONLY_LATEST로 받아 쌓이지 않게 합니다.

## 분류와 진행률

AI는 최근 특징 창에서 운동 종류를 분류하고, 운동별 상태 머신은 관절과 자세의 단계 순서를 확인합니다. 처음 15개 유효 시간행 이후부터 매 프레임 추론합니다. 입력 프레임 속도와 모델 입력 30Hz는 독립적입니다.

분류 확정에는 모델 점수 임계값, 1·2순위 점수 차이, 200ms 연속 일치가 필요합니다. 모델 점수는 확률로 보정하지 않았습니다. 운동별 잠정 상태 추적을 함께 유지해 분류가 늦게 확정되어도 이전 단계 관측을 이용합니다. 특징 창은 6초이고 반복 단계 상태는 최대 15초 유지합니다.

단계 추적의 기준:

- 스쿼트/푸쉬업: 준비 → 하강 → 기준 각도 도달 → 상승 → 최종 자세 안정. 0–50–100%.
- 점프스쿼트: 하강 0–40%, 상승·도약 40–70%, 공중·착지·서기 70–100%.
- 버피: 몸 낮추기 0–20%, 다리 뻗기 20–40%, 다리 당기기 40–60%, 상승·도약 60–80%, 착지·서기 80–100%.

안정 시간은 최종 판정 조건이며, 자세를 유지하는 것만으로 기하학적 진행률이 증가하지는 않습니다. 동일 반복에서는 진행률의 역행을 막습니다. 최저 기준 전에 올라오는 부분 동작은 반복으로 세지 않습니다. 시작 자세를 관측하지 못한 동작은 완료로 세지 않습니다.

완료 후보는 분류 확정 후 기본 500ms 확인 구간을 지나야 집계합니다. 후보 유효 시간은 완료 관측 후 1500ms입니다. 분류가 너무 늦으면 해당 반복은 누락될 수 있습니다. 점프가 관측되면 스쿼트 후보를 취소합니다. 이미 집계한 반복과 시작 시간이 겹치는 다른 운동 후보를 제외해 동일 동작을 중복 집계하지 않습니다.

초기 구현은 관절 임계값과 영상 발목/골반 이동을 사용하는 휴리스틱입니다. 운동 자세의 정확성, 측정 장비 수준의 비행 판정, 모든 버피 변형을 보장하지 않습니다. 카메라 이동·가림·프레임 누락·신체 비율에 따른 오차는 실제 수집 데이터로 평가해야 합니다.

## 수집 앱과 라벨링

촬영 대상은 1인, 전신 노출, 고정 사선입니다. 수집 라벨은 저장 파일의 헤더에만 들어갑니다. 앱은 원본 영상과 오디오를 저장하지 않으며, 파일 내보내기는 Android 문서 선택기를 사용합니다. 참가자 ID를 동일하게 유지해야 train/test에 같은 사람이 섞이지 않습니다.

라벨링 도구는 외부 서비스 없이 브라우저에서 실행하며 좌표 골격 재생·프레임 이동·단계 기록·구간 삭제·라벨 다시 불러오기를 제공합니다. 원본 영상 없이 정확히 구분하기 어려운 자세가 있을 수 있으므로 데이터 수집과 검토 절차를 함께 점검해야 합니다.

재생 속도는 프레임 간격을 따라가되 긴 유실 구간은 최대 100ms 대기로 압축합니다. 엔진에는 원본 타임스탬프를 전달하므로 실제 시간 간격 기준으로 평가됩니다. 예측 내보내기는 파일 재생 결과에만 제공됩니다.

## 학습·확장

데이터는 먼저 참가자 단위로 train/validation/test로 분할합니다. 중복 세션 ID를 거부하고, 모든 분할에 모든 클래스가 있어야 합니다. 시계열 창과 표준화 통계는 분할 이후 생성합니다. 학습 순서와 분할 seed는 보고서에 기록합니다.

모델은 32채널 causal Conv1D 6층(dilation 1,2,4,8,16,32), 마지막 시점 선택, softmax로 구성합니다. 가장 낮은 validation loss의 가중치를 내보냅니다. validation에서 확신도·마진 임계값을 선택하고 test는 최종 평가·변환 비교에만 사용합니다. 큰 데이터셋에서는 현재의 메모리 기반 창 생성·학습 로더를 스트리밍 로더로 교체해야 합니다.

운동 추가 시 새 데이터·라벨링 단계·학습 출력과 `ExerciseDefinition`을 함께 추가합니다. 특징이 기존 운동을 구분하기 부족할 때는 특징 규격 버전을 올리고 Kotlin/Python 양쪽을 수정하며 공통 fixture도 갱신합니다. 런타임은 모델에 있는 각 운동 ID의 단계 정의를 요구합니다.

공개 저장소 배포·Maven 원격 업로드·실제 데이터 수집·iOS 구현은 이번 작업에서 수행하지 않습니다.
